# Semantic layer

*Français : [semantic-layer.md](../semantic-layer.md)*

The semantic layer gives business names to the applied Gold model: what the agent
understands, what the interface shows, what analysts work with. It is generated by
deterministic rules (`forja_core.semantic.generate`), versioned in the catalog and
editable by an engineer. Labels and synonyms are in French in 0.1, like the interface.

## Content

### Metrics

| Field | Example (`prix_moyen`, average unit price) |
|---|---|
| `name`, `label`, `description` | `prix_moyen`, « Prix moyen unitaire » |
| `fact` | `fct_ventes` |
| `kind` | `aggregate` (aggregate of a fact column) or `ratio` (of two metrics) |
| `aggregation`, `column` | aggregates: `sum`, `count`, `count_distinct`, `min`, `max` |
| `numerator`, `denominator` | ratios: `montant`, `quantite` |
| `formula` | `sum(montant) / sum(quantite)` |
| `additivity` | `additive`, `semi_additive`, `non_additive` |
| `non_additive_dimensions` | semi-additive metrics: the time dimensions |
| `unit`, `format` | `EUR`, `currency` |
| `synonyms`, `hidden`, `default` | `["prix moyen", "prix unitaire moyen", …]` |

Generation rules:

- a Gold `sum` measure becomes an additive metric (`semi_additive` when its name reads
  as a balance: stock, balance, outstanding, headcount); `count` is additive;
  `count_distinct`, `min`, `max` are not additive;
- the id of a header joined to the fact (the `id_commande` of order lines) gives a
  distinct count: `nb_commandes`, « Nombre de commandes » (not additive: one order
  covers several products);
- **a non-additive value is always the ratio of two additive metrics, never an average
  of averages**: `prix_moyen = sum(montant) / sum(quantite)` (price weighted by
  quantity), `panier_moyen = sum(montant) / count_distinct(id_commande)`. The heuristic
  Gold plan therefore declares the unit price with the aggregation `none`: it computes
  `montant` row by row and is never aggregated;
- an `avg` or `none` measure without amount or quantity becomes the ratio of its sum to
  the number of fact rows;
- French labels and synonyms: a common vocabulary (`montant` → « Chiffre d'affaires »,
  synonyms CA, ventes, recettes…; `quantite` → « Quantité vendue ») and otherwise a label
  derived from the name (`date_commande` → « Date de commande »).

### Dimensions and attributes

| Type | Source | Example |
|---|---|---|
| `standard` | a Gold dimension related to the fact by a foreign key | `client` (dim_clients, `client_key`) |
| `degenerate` | the degenerate dimensions kept on the fact | `commande` (id_commande, num_ligne, statut) |
| `time` | one role of `dim_date` per date key of the fact | `date_commande` |

Each attribute has a label, a type (`text`, `number`, `date`, `boolean`), its
synonyms, `pii` (the personal data type inherited from the Silver plan) and
`filterable`: a non-personal text attribute whose distinct values can be read
**locally** to resolve a filter (« Lyon » → `client.ville = 'Lyon'`). A historized
(SCD2) dimension is marked `historized`: its attributes are those valid at the date of
the fact. `display_attribute` is the attribute used when the dimension is asked for by
its name (« par produit », per product → `produit.libelle`).

Generated hierarchies: calendar `annee > trimestre > mois > date` for each time
dimension, geography (`pays > region > departement > ville`) and catalog
(`categorie > sous_categorie > libelle`) when the attributes exist.

### References

A metric is referred to by its name (`montant`), an attribute by
`dimension.attribute` (`client.ville`), a time dimension by its name
(`date_commande`); the grains are `jour`, `semaine`, `mois`, `trimestre`, `annee`.

## Versions and edits

- The layer is generated again at the end of each successful `build_gold` (a step of
  the run, before it is announced done) and on demand
  (`POST /projects/{id}/semantic-layer/regenerate`). A new version is created only when
  the Gold model or the edits changed.
- An engineer edits with `PATCH /projects/{id}/semantic-layer` a list of
  **overrides**: `target` (`metric:montant`, `dimension:client`,
  `attribute:client.ville`), `label`, `description`, `synonyms` (replaces),
  `add_synonyms` (adds), `hidden`. Overrides are stored apart (`semantic_overrides`) and
  applied again at each generation: a manual edit is never overwritten. An override
  whose target leaves the Gold model is kept and logged
  (`semantic_overrides_orphaned`).
- A hidden element disappears for analysts and for the agent; engineers see it with
  its marker.

## Synonym proposals

An analyst (often after a question of the agent) proposes a synonym:
`POST /projects/{id}/semantic-layer/synonym-proposals`
(`{"target": "metric:montant", "synonym": "encaissements", "mart_request_id": …}`).
An engineer accepts it (`POST /synonym-proposals/{id}/accept`: the synonym is added by
an override and a new version is created) or rejects it.

Forja also proposes French synonyms for common English column names (`amount`,
`customer`, `order`, `price`, `quantity`, `date`, `city`...), from a deterministic
dictionary (`ENGLISH_WORDS` and `ENGLISH_PHRASES` in `semantic/labels.py`): `amount`
gets « montant » and the vocabulary of `montant` (« chiffre d'affaires », « CA »...),
`order_date` gets « date de commande ». These proposals (`origin: "dictionary"`,
`proposed_by: "forja"`) are created at each generation of the layer, wait in the same
queue and apply only once an engineer accepts them; a synonym already present, or
already proposed (even rejected), is not proposed again.

## API

| Method | Route | Role |
|---|---|---|
| `GET` | `/projects/{id}/semantic-layer?version=` | all (without hidden elements for analysts) |
| `GET` | `/projects/{id}/semantic-layer/versions` | all |
| `PATCH` | `/projects/{id}/semantic-layer` | engineer |
| `POST` | `/projects/{id}/semantic-layer/regenerate` | engineer |
| `POST` / `GET` | `/projects/{id}/semantic-layer/synonym-proposals` | all (an analyst sees their own) |

## Example: the e-commerce demo

| Metric | Formula | Additivity |
|---|---|---|
| Chiffre d'affaires (revenue, EUR) | `sum(montant)` | additive |
| Quantité vendue (units sold) | `sum(quantite)` | additive |
| Nombre de lignes (order lines) | `sum(nb_lignes)` | additive |
| Nombre de commandes (orders) | `count_distinct(id_commande)` | not additive |
| Panier moyen (average basket, EUR) | `sum(montant) / count_distinct(id_commande)` | not additive |
| Prix moyen unitaire (average unit price, EUR) | `sum(montant) / sum(quantite)` | not additive |

Dimensions: `client` (id_client, nom, prenom, email are personal; ville, segment,
date_inscription), `produit` (code_produit, libelle, categorie, prix_unitaire, actif;
hierarchy category > product), `commande` (degenerate: id_commande, num_ligne, statut),
`date_commande` (calendar).
